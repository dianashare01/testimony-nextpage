# 온라인 전시관 둘러보기 — 만드는 법

전시장에서 찍은 360 사진을 홈페이지의 「온라인 전시관 3D」에 넣습니다.
바깥 프로그램이나 유료 뷰어(krpano 같은 것) 없이 직접 그립니다.

## 쓰는 파일

| 파일 | 하는 일 |
|---|---|
| `assets/tour.js` · `tour.css` | 둘러보기 화면 전부 |
| `tour/tour.json` | 전시실·지점 목록 |
| `tour/<번호>/px.jpg …` | 지점 하나의 사진 (정육면체 여섯 면) |
| `_tools/make-tour.js` | 목록을 다시 만듦 |
| `_tools/cube.ps1` · `equirect-to-cube.js` | 사진을 여섯 면으로 자름 |

## 1. 사진 받기

카메라가 **이미 펼쳐 준 360 사진**(정방형 파노라마, 가로가 세로의 두 배,
8192×4096 쯤)을 받는 것이 가장 좋습니다. 인스타360 앱에서 내보내면 이 모양입니다.

삼각대에 올리고 타이머로 찍어, **찍는 사람이 화면에 안 나오게** 합니다.
눈높이 150~160cm, 기울지 않게. 막대기는 카메라가 알아서 지웁니다.

> 합쳐지지 않은 `.insp` 원본만 있을 때는 `insp-to-pano.js` 로 먼저 폅니다.
> 아래 「어안 두 장을 직접 펴기」 참고.

## 2. 여섯 면으로 자르기

```powershell
.\_tools\cube.ps1 -In "C:\...\사진폴더" -Out .\tour -Size 1536
```

`tour\01\px.jpg … nz.jpg` 와 흐릿한 미리보기 `*-s.jpg` 가 생깁니다.
24장에 40초쯤 걸립니다. 이미 있는 폴더는 건너뜁니다.

**왜 여섯 면인가** — 8192×4096 한 장을 그대로 그림판에 올리면 휴대폰이
버티지 못합니다. 여섯 면으로 나누면 같은 또렷함을 절반 남짓한 기억칸으로 얻고,
위아래가 늘어나 낭비되던 자리도 없어집니다. 크게 당겨 봐도 덜 뭉갭니다.

`-Size` 는 한 면의 크기입니다. 1536 이면 펼친 사진 6100픽셀쯤에 해당합니다.
더 또렷하게 하려면 2048 로 올리면 되지만, 파일과 기억칸이 1.8배가 됩니다.

## 3. 목록 만들기

`_tools/make-tour.js` 위쪽 표만 고치고 돌립니다.

```bash
node _tools/make-tour.js
```

표의 한 줄이 지점 하나입니다.

```js
{ id: '03', title: '연표의 길 · 1975 — 1999', yaw: 0, fwd: 120 },
```

- `id` — `tour/` 안의 사진 폴더 이름
- `title` — 왼쪽 목록과 화면 위에 뜨는 이름
- `yaw` — **들어갔을 때 처음 보는 방향**(도). 0이 사진 한가운데, +가 오른쪽.
  바닥 화살표·‹›·W/S·왼쪽 목록 **어느 길로 들어와도 이 각도로 시작**합니다
- `fwd` — **다음 지점으로 걸어가는 방향**(도). 바닥 화살표가 이 자리에 섭니다
- `back` — 앞 지점으로 되돌아가는 방향(도). 안 적으면 `fwd` 반대쪽

화살표가 벽을 가리키거든 그 숫자만 고치고 다시 돌리면 됩니다.
화살표가 화면 밖에 있으면 가장자리에 붙어 **어느 쪽인지 이름과 함께** 알려 줍니다.

### 걸어간 방향을 사진에서 재기

```powershell
.\_tools\walk-dir.ps1 -In "C:\...\사진폴더"
```

이웃한 두 사진을 견주어 `fwd`·`back` 에 넣을 각도를 계산해 줍니다.
카메라가 한 걸음 옮기면 걸어간 쪽은 제자리에 있고 옆에 있는 것일수록
크게 밀리는데, 그 밀린 양이 그리는 sin 곡선에서 방향을 꺼냅니다.

「믿음」이 **0.3 아래면 눈으로 확인**하세요. 흰 벽뿐인 방은 맞춰 볼 무늬가
없어서 값이 흔들립니다.

전시실 묶음(`no`, `name`)은 `index.html` 의 전시실 단추 번호와 맞춰야
그 단추를 눌렀을 때 그 전시실로 바로 들어갑니다.

## 4. 보는 사람이 쓸 수 있는 것

| | |
|---|---|
| 끌기 | 둘러보기 |
| 휠 · 두 손가락 · ＋－ 단추 | 확대·축소 |
| **두 번 누르기** | 그 자리를 당겨 봄 (글자·작품 확대) |
| 바닥 화살표 · ‹ › · **W** **S** | 앞뒤 지점 이동 |
| **A** **D** · 화살표 키 | 좌우 둘러보기 |
| ▶ | 자동 플레이 — 천천히 돌아보다 다음 지점으로 넘어감 |
| 🏠 | 처음 지점으로 |
| ⛶ | 전체 화면 |
| 왼쪽 목록 | 전시실·지점 바로 가기 |
| ☰ (휴대폰) | 목록 열기 |

자동 플레이가 한 지점에 머무는 시간은 `tour.json` 의 `dwell`(초)입니다.

## 5. 작품·글자 들여다보기 (선택)

지점에 `spots` 를 넣으면 그 자리에 동그란 표시가 생기고, 누르면 큰 사진이
뜹니다. 휠과 손가락으로 더 크게 볼 수 있습니다.

```js
{ id: '13', title: '…', yaw: 0, fwd: 90, spots: [
  { yaw: -22, pitch: -4, label: '심달연 압화', text: '1927~2010', img: 'close/13a.jpg' },
] },
```

`img` 는 `tour/` 아래 경로입니다. **가까이서 따로 찍은 사진**을 넣어야
글자가 또렷합니다. 360 사진에서 잘라 쓰면 원본이 8192픽셀뿐이라
많이 당기면 뭉개집니다.

## 6. 켜고 끄기

`tour/tour.json` 맨 위 `"open": false` 로 두면 전시실을 눌러도
「오픈 준비 중입니다」 알림만 뜹니다. `true` 면 열립니다.

# 어안 두 장을 직접 펴기 (`.insp`)

인스타360 앱 없이, 합쳐지지 않은 원본을 직접 펼 때만 씁니다.

```powershell
.\_tools\pano.ps1 -In "<insp 폴더>" -Out "<나올 폴더>" -Width 8192 -Fov 196
```

속으로는 이렇게 돕니다.

1. **PowerShell `LockBits` 로 날것 그림을 떠냅니다.**
   큰 그림에 `Graphics.DrawImage` 를 쓰면 조용히 빈 그림이 나옵니다.
2. `insp-to-pano.js` 가 동그란 두 장을 펴서 한 장으로 잇습니다.
3. 다시 JPEG 로 저장합니다. `EncoderParameter` 의 화질 값은
   **반드시 `[long]` 으로** 넣어야 먹습니다.

2026-10-29 전시장 사진 기준: 원본 11904×5952, 시야각 **196** 이 가장 깔끔.

## 곁들이는 도구

```powershell
# 사진들을 한 장의 대지로 붙여 한눈에 보기
.\_tools\sheet.ps1 -In "<jpg 폴더>" -Out sheet.jpg -Cols 3 -Cell 620

# 흔들린 사진 걸러내기 (p99 500 아래면 글자가 뭉개집니다)
.\_tools\blur.ps1 -Tour .\tour -Out sharp.csv
```

`blur.ps1` 은 평균이 아니라 **가장 또렷한 칸(p99)** 을 봅니다.
평균으로 재면 '흰 벽뿐인 방'이 '흔들린 사진'과 구별되지 않습니다.

### 화살표 방향을 직접 고치기

사진만 봐서는 어느 쪽으로 걸어갔는지 기계가 못 가릴 때가 있습니다
(흰 벽뿐인 방은 맞춰 볼 무늬가 없습니다). 그럴 때는 직접 찍어 주시면 됩니다.

홈페이지 주소 뒤에 **`?edit=1`** 을 붙여 들어갑니다.

    https://testimony-nextpage.com/?edit=1#tour

왼쪽 위에 작은 상자가 뜹니다.

1. 화면을 끌어 **다음 지점으로 가는 쪽**을 보게 맞춥니다
2. 「여기가 다음 길」을 누릅니다 (뒤로 가는 길은 「여기가 뒤로 길」)
3. 지점을 옮겨 가며 똑같이 합니다
4. 다 됐으면 **「서버에 저장」** — 관리자 코드를 한 번 묻습니다

저장하면 모든 사람에게 그대로 보입니다. `make-tour.js` 를 고치지 않아도 되고,
GitHub 에 올릴 필요도 없습니다. 저장한 값이 표의 `fwd`·`back` 보다 우선합니다.

### 색이 이상할 때 (빨강↔파랑)

PowerShell 이 `LockBits` 로 떠 주는 `Format24bppRgb` 는 이름과 달리
**파랑·초록·빨강 차례**입니다. BMP 도 같은 차례라 그대로 옮기면 됩니다.
여기서 한 번 더 뒤집으면 빨강과 파랑이 바뀌어, 나무 바닥이 보랏빛이 됩니다
(2026-11-02 에 실제로 그랬습니다. `equirect-to-cube.js` 의 `writeBmp`).

확인하는 법 — 원본과 만든 면에서 같은 자리 색을 견줍니다.

```powershell
Add-Type -AssemblyName System.Drawing
$a = New-Object System.Drawing.Bitmap "원본.jpg"
$b = New-Object System.Drawing.Bitmap "tour\06\ny.jpg"   # ny = 발밑 바닥
"원본 {0}  큐브 {1}" -f $a.GetPixel([int]($a.Width/2),[int]($a.Height*0.86)), $b.GetPixel([int]($b.Width/2),[int]($b.Height/2))
```

바닥처럼 따뜻한 색(빨강이 가장 큼)에서 봐야 드러납니다. 흰 벽은 티가 안 납니다.
